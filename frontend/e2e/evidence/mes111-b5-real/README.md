# Real-stack Appica shell and keyboard evidence

This directory is generated by the production-auth Compose journey in
`e2e/real-mes128-keyboard.spec.ts`. It contains seven full-page screenshots for
the 1440px desktop and each 320px/390px phone project plus `manifest.json` with
screenshot hashes and dimensions, chronological HTTP methods/statuses/paths,
and PostgreSQL values asserted by the test. MES-158 additionally proves that
the production shell renders Appica Navigation/Input slots while Mesh remains
the authoritative `data-theme`/first-frame chain.

The journey uses no Playwright route handlers or mock server. The browser can
reach only the loopback-bound frontend; nginx proxies API and WebSocket traffic
to the private Compose network. PostgreSQL, Redis, MinIO, API, and gateway have
no host-published ports. Database evidence is read with `psql` inside the
private PostgreSQL container.

Reproduce from the repository root:

```bash
./frontend/e2e/mes128-real/gen-stack-env.sh --force
./frontend/e2e/mes128-real/run-e2e.sh
```

`stack.env` is gitignored, written with mode 600, and contains fresh strong
random credentials. The runner builds the stack, waits on the same-origin
readiness endpoint, runs all three viewport projects serially, then removes its
containers and volumes. The manifest deliberately excludes request bodies,
tokens, passwords, and test-account email addresses.
