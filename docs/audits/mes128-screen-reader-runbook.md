# MES-128 NVDA / VoiceOver 人工验收脚本

> 状态：等待具备对应桌面系统的人工执行。本文是运行脚本，不是通过证据。自动 axe、
> accessibility tree 或语义单测不得替代此记录。

## 环境与记录格式

至少完成下列一组；发布验收若要求双 AT，则两组都要完成：

| 组合              | 浏览器        | 必填版本信息                  |
| ----------------- | ------------- | ----------------------------- |
| Windows + NVDA    | Chrome stable | Windows、NVDA、Chrome 版本    |
| macOS + VoiceOver | Safari stable | macOS、VoiceOver、Safari 版本 |

记录人必须填写日期、AT/浏览器版本、viewport、每步实际播报、焦点目标、结果和截图/录屏文件。
不要只写“符合预期”。使用一套新建的测试账号，并在 production-auth 隔离栈上执行；不得接入
Playwright mock server。

## 前置检查

1. 以键盘启动浏览器并打开登录页，不使用鼠标。
2. 将浏览器内容宽度分别设为 320px 与 390px；两档各完整执行一次。
3. 确认第一个 Tab 是“跳到主内容”，激活后焦点落在唯一 `main`。
4. 确认页面标题、唯一 `h1`、landmark 列表和当前主题被 AT 正确识别。

## 六流程

| 步骤       | 仅键盘操作                                                              | 必须记录的读屏结果                                                                |
| ---------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 登录       | Tab 到邮箱/密码，输入后 Enter                                           | 字段名称、必填/错误说明、提交 busy/disabled 变化；成功后播报工作台标题            |
| 创建 issue | 进入 issue 列表，打开快速创建，填写标题并提交                           | Dialog 名称、焦点圈定、错误不丢输入；成功 live region 与新 issue 标识符           |
| 非拖拽移卡 | 打开看板，聚焦卡片，使用移动入口/方向键确认                             | 卡片名称、当前列/位置、目标列、确认/取消；完成后播报新列与位置，不触发 drag event |
| 评论       | 进入 issue 详情，聚焦评论编辑器，以 Ctrl/Cmd+Enter 提交                 | 编辑器名称、提交状态、新评论作者/正文与 live announcement；焦点不丢失             |
| 切工作区   | 用切换器选择第二工作区                                                  | 菜单展开/当前项/选中态；切换后新工作区名称和主标题，旧工作区对象不残留            |
| 搜索       | `/` 或 Ctrl/Cmd+K 聚焦统一搜索，输入第二工作区 issue，ArrowDown + Enter | 查询状态、结果数量、选中项；打开后播报正确工作区内的 issue 标题                   |

## 看板大列表连续性

1. 使用至少 250 张卡的 fixture 打开看板。
2. 默认虚拟模式下确认“使用完整读屏列表”按钮可发现、名称正确、`aria-pressed=false`。
3. 激活后确认 `aria-pressed=true`，并从第 1 张按 DOM 顺序连续浏览到第 250 张，不跳号、不重复。
4. 在完整列表模式内完成一次非拖拽移动，再切回虚拟模式；记录焦点归还和播报。

## Overlay、异常态与恢复

- 分别打开/关闭命令面板、帮助层、Dialog 与 Drawer：验证初始焦点、Tab/Shift+Tab 圈定、Esc
  关闭、焦点归还触发点。
- 对 loading、empty、error、permission、offline/stale 与长内容各抽查核心页：记录 status/alert
  是否只播报一次、错误影响与恢复动作是否可理解、刷新是否保留已有内容。
- 触发 `agent.trigger_skipped`：记录原因 toast、关闭按钮和 issue 动作的名称与焦点行为。
