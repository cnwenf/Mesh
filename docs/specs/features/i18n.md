# 国际化与时区(i18n)功能 Spec

> **所属层**:平台能力层(R2 必修-E,MES-2 强化轮必修)。
> **依赖的其他 Spec**:
> - `auth.md`(§2.2 `users`):`users.settings.locale`(账号级语言偏好,BCP-47,如 `zh-CN`)、`users.timezone`(账号级时区偏好,IANA,**既有字段**,本 Spec 明确其仅为展示偏好)、`users.settings.theme`(账号级主题偏好,README §6.12,与本 Spec 同属"展示层偏好"存储约定)。
> - `workspace.md`(§2.2 `workspaces.settings`):`workspaces.settings.default_locale`(工作区级默认 locale,**新增键约定**,需在 workspace.md §2.2 `settings` 键表同步登记,见 §2.3);既有列 `workspaces.timezone`/`workspaces.default_language` 与本键的关系见 §2.3。
> - `comment-inbox.md`:邮件摘要按**收件人** locale 渲染模板(README §6.13 通知投递 / §6.18 服务端职责)。
> - `import-export.md` / `analytics.md`:导出/报表在导出时声明 locale(README §6.18 服务端职责)。
> **被依赖方**:所有需要在界面渲染可见文案、日期/时间/数字/相对时间的模块,均以本 Spec 的消息目录与本地化规则为呈现依据;错误信息的本地化以 README §6.14 的稳定 `code` 为键。
>
> **全局一致性锚点(canonical anchor)**:本 Spec 是 [README.md](../README.md) §6.18「国际化与时区契约」的**详 Spec**。§6.18 已就**存储层(一切时间戳 UTC RFC3339)**、**locale 协商链**、**字符串外部化**、**本地化渲染**、**服务端职责**作出唯一权威契约;本 Spec 仅**展开其实现细节**(消息目录结构、目录拉取端点、偏好写入路径、UI 呈现与验收),**不复述、不改写契约原文**——凡与 §6.18 冲突,一律以 README 为准。相关契约锚点:设计 token/主题(§6.12)、错误码为稳定 key(§6.14)、通知与邮件投递(§6.13)、API 包络/错误/分页(§6.14)。

## 1. 功能描述

### 1.1 模块定位

本模块为 Mesh 提供**面向呈现层**的国际化与时区能力,与主题/暗色(README §6.12)共同构成前端呈现契约:

- **locale 协商**:按 §6.18 协商链确定每次渲染所用语言(BCP-47),首发 `zh-CN` + `en`。
- **字符串外部化**:一切界面可见文案经**消息目录**外部化,杜绝硬编码(§6.18)。
- **本地化渲染**:日期/时间/数字/相对时间按 `locale + 用户 timezone` 渲染;**时区化仅发生在展示层**——`users.timezone`(IANA)决定本地显示,输入值解析回 UTC 存储(§6.18)。
- **服务端模板 locale**:邮件摘要等服务端渲染产物按**收件人** locale 选模板;API 本身不翻译文案(§6.18)。

存储层语义不变:一切时间戳的**存储与传输一律 UTC RFC3339**(README §6.14/§6.18);locale 与 timezone 是展示偏好,**不落业务字段**。

### 1.2 功能点 + 用户场景表

| # | 功能点 | 说明 | 典型用户场景 |
|---|--------|------|--------------|
| L1 | locale 协商链 | 请求显式参数 → 用户偏好 → 工作区默认 → `en`(§6.18) | 中国团队默认中文界面,外籍成员个人页切英文 |
| L2 | 消息目录管理 | 按模块命名空间的 key + ICU MessageFormat 文案,版本化发布 | 新增 issue 模块文案,随版本拉取生效 |
| L3 | 日期/时间本地化 | 绝对时间按用户 timezone + locale 渲染 | `2026-07-25T08:00:00Z` 在上海显示为 16:00 |
| L4 | 数字本地化 | 千分位/小数点/货币按 locale 渲染 | velocity 图表 zh-CN 用 `1,234.5`,de-DE 用 `1.234,5` |
| L5 | 相对时间本地化 | "3 分钟前 / in 2 hours" 按 locale + 复数规则 | 看板卡片显示"5 分钟前更新" |
| L6 | 时区化展示 | 全量时间显示随 `users.timezone` 变化,存储值不变 | 同一截止日,沪/纽约成员各见本地时间并标注时区 |
| L7 | 输入解析回 UTC | 用户输入的本地时间解析为 UTC 存储 | 选"明天 9:00(本地)"落库为对应 UTC |
| L8 | 服务端邮件模板 locale | 邮件摘要按收件人 locale 选模板渲染 | 中文成员收中文摘要,英文成员收英文摘要 |
| L9 | 目录缓存与版本 | 客户端按 `version`/ETag 缓存目录,增量更新 | 文案发版后客户端命中新版本即拉取,否则 304 |

### 1.3 边界与非目标(明确不做什么)

- **后端 API 不做文案翻译**:API 一律返回**稳定 key + 结构化数据**(§6.18 服务端职责);面向用户的本地化文案由前端按 locale 渲染。错误响应同理:后端 `message` 保持英文/中性、不泄漏内部细节(README §6.14),前端按稳定 `code` 渲染本地文案(§3.4)。
- **RTL 布局**:本期声明为**可选增强**,不列入验收;消息目录与占位符设计需为其预留(逻辑属性而非硬编码左右),但默认语言 `zh-CN`/`en` 均为 LTR。
- **机器翻译**:不做。缺失翻译走回退链(§2.5),不自动机翻补齐。
- **不**新增业务表、**不**改写存储层时间语义(UTC 不变)、**不**自定义角色/权限模型(沿用 auth.md RBAC)。
- **不**约束前端框架(README §3.2):本 Spec 定义目录格式、端点与呈现规则,渲染实现由前端选型承载。

## 2. 数据模型与配置

> **全局契约引用**:本模块的 API 包络/错误/分页一律以 [README.md](../README.md) §6.14 为权威;locale 协商与本地化语义以 §6.18 为权威;主题偏好以 §6.12 为权威。本 Spec 仅引用、不重复定义。
>
> **不新增表**:本模块**无新表**,仅约定 `users.settings` / `workspaces.settings` 两处 JSONB 的键(PostgreSQL 16,既有 JSONB 列),与"存储层不落业务字段"一致(§6.18)。

### 2.1 偏好存储总览

| 偏好 | 载体 | 类型 | 默认 | 说明 |
|------|------|------|------|------|
| 账号语言 | `users.settings.locale` | string(BCP-47) | 缺省走协商链下一级 | 账号级语言偏好,如 `zh-CN`/`en-US` |
| 账号主题 | `users.settings.theme` | string | `system` | 见 README §6.12,与本键同为账号级展示偏好 |
| 账号时区 | `users.timezone` | string(IANA) | `'UTC'` | **既有字段**,仅为展示偏好;存储层时间恒 UTC |
| 工作区默认语言 | `workspaces.settings.default_locale` | string(BCP-47) | `en` | **新增键约定**,协商链"工作区默认"级,见 §2.3 |

> `users.settings` / `workspaces.settings` 均采用**按键浅合并**写入(PATCH 语义,与 workspace.md §2.2 一致):仅覆盖请求中出现的键,未出现的键保持原值;已知键做类型校验,非法返回 400 `validation_error`。

### 2.2 `users` 偏好键(auth.md §2.2)

| 键 | 类型 | 默认 | 说明 |
|----|------|------|------|
| `users.settings.locale` | string \| null | `null`(走协商链下一级) | BCP-47(如 `zh-CN`);为 `null` 时协商链跳过本级,落到工作区默认 |
| `users.settings.theme` | string | `"system"` | 主题偏好,见 README §6.12(本 Spec 不展开) |
| `users.timezone` | string | `"UTC"` | **既有 IANA 字段**;仅决定展示层本地时间,不改变任何存储/传输的 UTC 值(§6.18) |

> **说明**:`users.settings.locale`/`users.settings.theme` 与 `users.timezone` 均属账号级**展示偏好**,语义对齐 README §6.12/§6.18;本 Spec 仅消费这些键,其在 `users` 上的列存在性与写入端点归 auth.md(`PATCH /api/v1/users/me`,§3.1)。本 Spec **不**要求 auth.md 新增列;若实现侧 `users.settings` JSONB 尚未登记上述键,按 auth.md §2.2 既有 JSONB 约定补登记即可,不新增表。

### 2.3 `workspaces` 偏好键(workspace.md §2.2,新增键约定)

| 键 | 类型 | 默认 | 说明 |
|----|------|------|------|
| `workspaces.settings.default_locale` | string | `"en"` | 工作区级默认 locale(BCP-47);协商链"工作区默认"级的**权威读取键**(§6.18)。**需在 workspace.md §2.2 `settings` 已知键表同步登记**(本 Spec 为该键约定的 owner) |

**与既有列的关系(避免跨 Spec 不一致)**:workspace.md §2.2 已有顶层列 `workspaces.default_language`(短码,默认 `'en'`)与 `workspaces.timezone`(IANA,默认 `'UTC'`)。为维持单一权威来源、不引入第二套协商来源:

- 协商链"工作区默认 locale"一律读 **`workspaces.settings.default_locale`**(§6.18 权威键);
- 既有 `workspaces.default_language` 与本键表达同一概念,服务层在写入任一处时**同步两者取值**(BCP-47 归一),对外协商只暴露 `settings.default_locale`;
- 既有 `workspaces.timezone` 为**工作区级**时区(用于工作区维度的默认展示与跨时区标注),**用户看到的本地时间以 `users.timezone` 为准**(用户级覆盖工作区级);跨时区协作场景 UI 同时标注时区(§6.18)。

### 2.4 消息目录结构

**命名空间按模块**:key 采用 `<模块>.<子域>.<语义>` 的点分层级,模块段与 `docs/specs/features/*.md` 模块对齐,杜绝全局平铺与跨模块撞名:

```
issue.create.title          "新建工作项"
issue.create.submit         "创建"
issue.detail.due_date       "截止时间"
issue.status.todo           "待办"
comment.placeholder         "写下评论,@ 成员或 agent 协作"
notification.assigned       "{actor} 把 {identifier} 分派给了你"
common.cancel               "取消"
common.save                 "保存"
error.forbidden             "你没有权限执行此操作"
error.not_found             "未找到该资源"
```

**占位符(ICU MessageFormat)**:文案中的动态值用 ICU 占位符表达,前端以结构化参数(来自 API 返回的稳定数据)填充,**后端不下发已拼好的本地化句子**:

```
notification.comment_count  "{count, plural, =0 {暂无评论} one {# 条评论} other {# 条评论}}"
execution.duration          "运行耗时 {minutes, plural, one {# 分钟} other {# 分钟}}"
member.joined               "{name} 于 {date, date, medium} 加入"
issue.position              "第 {n, number} 项,共 {total, number} 项"
```

**复数规则**:按 CLDR 复数类别(`zero/one/two/few/many/other`)经 ICU `plural` 选择;`zh-CN` 仅 `other`,`en` 有 `one/other`,目录条目按目标语言实际类别提供分支,缺分支以 `other` 兜底。

**目录文件格式**(每 locale 一份,服务端聚合下发,§3.1):

```json
{
  "locale": "zh-CN",
  "version": "9f2c1ab4",
  "messages": {
    "issue.create.title": "新建工作项",
    "notification.comment_count": "{count, plural, =0 {暂无评论} other {# 条评论}}"
  }
}
```

### 2.5 目录版本与缺 key 回退

- **版本**:`version` 为该 locale 目录内容的不可变哈希(如内容 SHA-256 前 8 位),内容变更即换版本;客户端据此做 ETag 缓存(§3.1)。
- **缺 key 回退链(三级)**:请求 locale 缺某 key → 回退 `en` 同 key → 仍缺则回退 **key 本身**(`issue.create.title` 原样显示),并**上报缺失**(§4.5)。回退仅影响该 key 的单点渲染,不中断整页。
- **目录完整性校验**:发版前对每个非 `en` locale 做 key 覆盖检查,缺失项进入"待翻译"清单;`en` 为**权威源语言**,一切 key 必须先在 `en` 登记。

## 3. 接口设计

> REST 基础路径 `/api/v1`;鉴权 `Authorization: Bearer <token>`(auth.md)。**成功包络、错误信封、HTTP 语义、幂等写一律以 README §6.14 为权威**;时间一律 RFC3339 UTC。

### 3.1 端点清单

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/i18n/catalog?locale=&version=` | 拉取指定 locale 的消息目录,带版本缓存(ETag) | 已登录(目录可按工作区可见模块过滤) |
| GET | `/api/v1/i18n/locales` | 列出受支持 locale 清单(`zh-CN`/`en` 首发) | 已登录 |
| PATCH | `/api/v1/users/me` | 写 `settings.locale` / `timezone`(auth.md 既有端点,本 Spec 仅声明其承载的键) | 本人 |
| PATCH | `/api/v1/workspaces/{id}` | 写 `settings.default_locale`(workspace.md 既有端点,§2.3) | admin |
| POST | `/api/v1/i18n/missing`(开发期) | 上报缺失 key(§4.5);生产可关闭/仅审计 | 已登录 |

### 3.2 请求/响应 JSON 示例

**拉取消息目录** `GET /api/v1/i18n/catalog?locale=zh-CN`
```json
// 200 Response(命中,返回完整目录;ETag 头携带版本)
// HTTP: ETag: "9f2c1ab4"
{
  "data": {
    "locale": "zh-CN",
    "version": "9f2c1ab4",
    "messages": {
      "issue.create.title": "新建工作项",
      "issue.create.submit": "创建",
      "notification.comment_count": "{count, plural, =0 {暂无评论} other {# 条评论}}"
    }
  }
}
// 304 Not Modified:客户端带 If-None-Match: "9f2c1ab4" 且版本未变 → 不返回 body,沿用本地缓存
```

> 请求中的 `version=` 与 `If-None-Match` 等价表达"客户端当前版本";`locale` 缺省时按 §3.3 协商链解析。目录体可能较大,响应启用标准 HTTP 缓存(`ETag`/`Cache-Control`),减少重复传输。

**写账号偏好** `PATCH /api/v1/users/me`(auth.md 既有端点)
```json
// Request(按键浅合并;仅覆盖出现的键)
{ "settings": { "locale": "en-US" }, "timezone": "America/New_York" }
// 200 Response:返回更新后的用户对象(README §6.14 单对象包络)
{ "data": { "id": "u-1", "settings": { "locale": "en-US", "theme": "system" },
            "timezone": "America/New_York", "updated_at": "2026-07-25T08:00:00Z" } }
```

**写工作区默认 locale** `PATCH /api/v1/workspaces/{id}`(workspace.md 既有端点)
```json
// Request
{ "settings": { "default_locale": "zh-CN" } }
// 200 Response:返回工作区对象;触发 workspace.updated 实时事件(workspace.md §3.5)
```

### 3.3 `Accept-Language` 协商处理规则(§6.18 协商链)

按 §6.18 优先级实现,从高到低:

1. **请求显式参数**:查询参数 `?locale=` 优先于 `Accept-Language` 头(二者同属"请求显式参数"级,显式参数更明确);
2. **用户偏好** `users.settings.locale`(为 `null` 则跳过);
3. **工作区默认** `workspaces.settings.default_locale`(§2.3 权威键);
4. **系统回退** `en`。

**`Accept-Language` 解析细节**:
- 按 quality 值(`q`)降序取候选,如 `zh-CN,zh;q=0.9,en;q=0.8` → 候选序 `[zh-CN, zh, en]`;
- **BCP-47 匹配**:先精确匹配(`zh-CN`);不中则按语言主干回退(`zh-TW` → `zh-CN`,同语言取受支持的区域变体);仍不中则取下一候选;全部不中落 `en`;
- 非法/未知 locale 值(非 BCP-47、不在受支持清单)一律忽略并继续协商,不返回 400(协商是尽力而为,失败回退 `en`)。

### 3.4 错误码 key 与本地化 message 的关系(§6.14)

- README §6.14 的 `code`(snake_case)是**稳定 key**,跨 locale 不变(如 `forbidden`/`not_found`/`validation_error`);
- 后端错误信封 `{"error":{"code","message","details"}}` 中的 `message` **保持英文/中性、不泄漏内部细节**(§6.14),**不做翻译**;
- **前端按 `code` 在消息目录取本地文案**(`error.forbidden` → "你没有权限执行此操作");`details` 提供结构化字段供占位符填充(如 `{field}`);
- 新增错误码必须**同步**在 `en` 目录登记 `error.<code>` 键,否则前端回退显示 `code` 本身(§2.5)。

### 3.5 错误码表(模块专属)

| HTTP | code | 场景 |
|------|------|------|
| 400 | `validation_error` | `settings.locale`/`timezone`/`default_locale` 非法(非 BCP-47 / 非 IANA) |
| 401 | `unauthorized` | 凭证缺失/无效(README §6.14 canonical code) |
| 403 | `forbidden` | 非 admin 写工作区 `default_locale` |
| 404 | `not_found` | `locale` 不在受支持清单且以路径/资源形式请求 |
| 429 | `rate_limited` | 目录拉取触发限流(auth.md;`missing` 上报从严限流防滥用) |

> 公共 HTTP 语义与错误信封不重复定义(README §6.14)。

## 4. UI/UX 设计

### 4.1 语言/时区设置入口

- **用户级(账号偏好)**:设置 → 个人偏好 → 语言(下拉,受支持 locale 清单,标注"立即生效")+ 时区(下拉,IANA,默认提示"按浏览器时区检测")。写入经 `PATCH /api/v1/users/me`(§3.1)。
- **工作区级默认**:设置 → 基本信息 → 默认语言(衔接 workspace.md §4.1「基本信息表单」的语言下拉),写入 `workspaces.settings.default_locale`,仅 admin 可见可改;**标注"作用于未单独设置语言的成员"**。
- 两级关系可视化:用户级显示"跟随工作区默认(zh-CN)"占位,显式选择后改为具体值并提供"恢复跟随默认"。

### 4.2 locale 切换即时生效(无刷新)

- 切换语言后,前端按新 locale 拉取/激活对应目录(命中缓存即生效,无需整页刷新),**已渲染文案就地更新**;
- 目录按 `version` 缓存(§3.1),仅在版本变化时重新拉取;
- 切换不改变任何存储数据,纯呈现层(§6.18)。

### 4.3 时区切换对全量时间显示生效

- 切换 `users.timezone` 后,**全量**时间显示(截止日、创建时间、运行耗时锚点、评论时间)即时按新时区重渲染;**存储值不变(UTC)**;
- **跨时区示例**(同一截止日 `2026-07-25T18:00:00Z`):

  | 成员 timezone | 显示 |
  |------|------|
  | `Asia/Shanghai`(UTC+8) | `2026-07-26 02:00 (GMT+8)` |
  | `America/New_York`(UTC-4,夏令时) | `2026-07-25 14:00 (GMT-4)` |
  | `UTC` | `2026-07-25 18:00 (UTC)` |

- **跨时区协作标注**:截止日/周期等共享时间,除本地时间外**同时标注时区**(如悬浮显示 UTC 原值与其他成员时区),避免"我以为的 9 点 ≠ 你的 9 点"(§6.18)。

### 4.4 本地化数字/日期格式示例(zh-CN vs en-US)

| 类别 | zh-CN | en-US |
|------|-------|-------|
| 日期(短) | `2026/7/25` | `7/25/2026` |
| 日期(中) | `2026年7月25日` | `Jul 25, 2026` |
| 时间(12/24h) | `16:00`(24h) | `4:00 PM`(12h) |
| 数字千分位 | `1,234.5` | `1,234.5` |
| 数字(de-DE 对照) | — | `1.234,5` |
| 相对时间 | `3 分钟前` / `2 小时后` | `3 minutes ago` / `in 2 hours` |
| 复数 | `5 条评论`(无单复数变化) | `1 comment` / `5 comments` |

### 4.5 "翻译缺失"的开发期可见标记

- **开发期**:命中回退链(key 本身或 `en`)的文案以**可见标记**呈现(如包裹 `⚠[issue.create.title]` 或高亮边框),便于译缺排查;生产构建关闭该标记。
- **上报**:命中回退时前端经 `POST /api/v1/i18n/missing` 上报 `{locale, key, fallback}`,聚合生成"待翻译清单"(生产可关闭,仅审计);遵循防失控——上报从严限流、去重(同 locale+key 窗口内合并)。
- 缺失标记**不影响功能可用性**(回退保证可读),仅作可见性提示。

## 5. 验收标准

### 5.1 功能性

- [ ] **协商链优先级正确**:请求显式参数(`?locale=` > `Accept-Language`)→ `users.settings.locale` → `workspaces.settings.default_locale` → `en`;任一级缺省则跳到下一级,`users.settings.locale=null` 时落到工作区默认(§6.18)。
- [ ] **`Accept-Language` 解析**:按 `q` 值排序、BCP-47 精确 → 语言主干回退;非法/未知 locale 忽略并回退 `en`,不返回 400(§3.3)。
- [ ] **文案外部化**:一切界面可见文案经消息目录外部化;**抽查核心页面(看板/issue 详情/收件箱/成员/设置)无硬编码可见文案**;错误码经 `error.<code>` 键本地化(§6.18/§3.4)。
- [ ] **时间显示随时区变化、存储值不变**:切换 `users.timezone` 后全量时间显示按新时区重渲染,而 API 返回与数据库存储的时间戳**仍为原 UTC 值不变**(§6.18);同一截止日在不同时区成员处显示各自本地时间并标注时区(§4.3)。
- [ ] **输入解析回 UTC**:用户以本地时间输入(如"明天 9:00")解析为对应 UTC 落库,跨时区成员看到等价的各自本地时间(§6.18)。
- [ ] **复数/占位符正确**:ICU `plural` 按语言 CLDR 类别选择(`en` 区分 one/other,`zh-CN` 仅 other);占位符以结构化参数填充,后端不下发已拼好的本地化句子(§2.4)。
- [ ] **缺 key 回退链生效**:请求 locale 缺 key → `en` → key 本身,三级回退,单点回退不中断整页;命中回退触发上报(§2.5/§4.5)。
- [ ] **目录缓存 ETag 有效**:`GET /i18n/catalog` 返回 `ETag: <version>`;客户端带 `If-None-Match` 且版本未变时返回 **304 无 body**;版本变化时返回新目录(§3.1/§3.2)。
- [ ] **服务端邮件按收件人 locale**:同一 issue 的摘要邮件,中文收件人收 `zh-CN` 模板、英文收件人收 `en` 模板(README §6.13/§6.18)。
- [ ] **后端 API 不翻译**:API 响应只含稳定 key + 结构化数据,不含已翻译的界面文案;错误 `message` 保持英文/中性、不泄漏内部细节(§6.14/§6.18)。
- [ ] **偏好写入经既有端点**:用户偏好经 auth.md `PATCH /users/me`、工作区默认经 workspace.md `PATCH /workspaces/{id}`,按键浅合并;非法 locale/timezone 返回 400 `validation_error`(§3.1/§3.5)。
- [ ] **新增键已同步登记**:`workspaces.settings.default_locale` 已在 workspace.md §2.2 `settings` 键表登记(§2.3),与既有 `default_language` 列取值同步,协商只暴露单一权威键。

### 5.2 性能

- [ ] 目录拉取命中缓存(304)时 P95 < 30ms(无 body 传输);首次全量拉取启用压缩与 `Cache-Control`。
- [ ] 协商链解析(含 `Accept-Language` 排序与 BCP-47 匹配)每请求开销 P95 < 5ms(受支持清单内存化)。
- [ ] 时区/locale 切换的界面重渲染在 1s 内完成,无整页刷新(§4.2/§4.3)。
- [ ] `missing` 上报去重 + 从严限流,不构成写放大或滥用面(§4.5)。

### 5.3 安全与一致性

- [ ] locale/timezone 仅影响呈现层,**不改任何存储/传输的 UTC 时间值**,不落业务字段(§6.18)。
- [ ] 占位符填充以**结构化数据**渲染,转义到位,**不**把外部内容作为 HTML/指令注入(衔接 README §6.15 不可信内容处理)。
- [ ] 错误本地化以前端按稳定 `code` 取目录实现,后端不因 locale 改变 `code` 或泄漏内部细节(§6.14)。
- [ ] 目录与 `missing` 端点经鉴权与限流(auth.md);`missing` 上报内容不含敏感数据。
- [ ] **无暴露参考来源**:目录文案、key、注释中不含任何对标产品名称或参考来源信息,Mesh 以独立原创面貌呈现。

### 5.4 可观测

- [ ] 缺 key 回退命中可被聚合统计(按 locale + key),用于驱动翻译补齐;生产环境关闭可见标记但保留(可关闭的)审计上报(§4.5)。
- [ ] 目录版本(`version`)变更可追溯,文案发版与客户端拉取版本可观测对账。
