## 1. 目标与设计原则

目标不是“换一套颜色”，而是把现有可用功能收敛为一致、清晰、可信、可高频使用的
完成品：

1. **任务优先**：用户进入页面后 3 秒内能辨认当前位置、主任务、当前状态和下一步。
2. **信息密度可控**：桌面端适合高频协作；移动端保留完整关键路径，不做“隐藏侧栏后
   无法导航”的只读残版。
3. **系统一致性**：同一语义只有一种视觉与交互表达；页面不得自行发明按钮、表单、
   标签、表格、空态或弹层。
4. **AI 队友可见但不喧宾夺主**：人类与 agent 同一信息层级，以头像、类型徽标、运行
   状态和容量表达差异，不靠大面积品牌色制造噪声。
5. **双主题独立校准**：暗色不是亮色反相；层级、边界、悬浮、禁用、危险态和图表均
   分主题校准。
6. **反馈就地发生**：保存、拖拽、评论、搜索、切换工作区等操作在动作附近反馈；
   错误说明原因、影响和恢复动作。
7. **渐进披露**：默认界面只显示高频信息；高级筛选、编排、审计和危险操作按需展开。

### 1.1 非目标

- 不改变既有业务权限、实体关系、状态机或 API 契约。
- 不引入可配置主题市场、页面搭建器或品牌皮肤。
- 不为“看起来高级”而堆叠渐变、玻璃效果、强阴影或无意义动画。
- 不以单页特例修补代替 token、组件和模板层的统一。

## 2. 现状审查与差距清单

本轮基线来自路由、设计 token、组件、功能 CSS 与已入库视觉快照的逐项检查。后续
实现若现状已由 MES-107 或其他 PR 改变，以最新代码为准，但目标规范不变。

### 2.1 可量化基线

| 项目 | 当前基线 | 差距 |
| --- | ---: | --- |
| 路由声明 | 42 | 覆盖广，但缺少统一页面模板与逐路由视觉门禁 |
| 侧栏一级入口 | 15 | 全部平铺，无分组、图标、折叠与移动端替代导航 |
| 功能层 CSS | 18 个文件、约 6,583 行 | 大量页面自定义控件与布局，维护成本高 |
| 设计系统组件 | Button、Input、Select、Dialog 等约 11 个 | 缺表格、菜单、抽屉、标签、头像、Tabs、Tooltip、页面头等 |
| 原生交互标签 | 业务源码约 163 处 | 状态、尺寸、焦点、触控与暗色表现无法统一 |
| 字号 token | 14 / 16 / 20px 三档 | 无标题、说明、数据、代码与紧凑 UI 的完整层级 |
| 页面级宽度媒体查询 | shell、聊天、技能、Issue 四类 | 看板、成员、收件箱、自动化等缺少明确响应式策略 |
| 视觉回归 | 6 页 × 2 主题 × 桌面/平板 | 缺登录、首页、项目、设置、自动化、统计与手机视口 |

### 2.2 P0：阻断“完成品”观感的问题

1. **脚手架与占位残留**：首页仍为演示区并调用不存在的 demo API，登录页残留开发
   token 入口和阶段文案；由 MES-107 先清理。
2. **信息架构有断链**：侧栏存在“技能”入口但当前路由树未注册对应页面；中文侧栏两
   个不同模块均显示“自动化”，用户无法预判目的地。
3. **移动端导航消失**：`≤768px` 直接隐藏侧栏，没有底部导航、抽屉或“更多”入口；
   用户进入深页后无法可靠切换模块。
4. **桌面空间分配失衡**：看板快照中操作区与列集中在主区右半侧，左侧出现大面积
   无意义留白；看板没有把可用宽度用于横向列和卡片信息。
5. **表格溢出**：成员页在 1024px 已出现右侧列和操作被裁切；长生命周期文案还直接
   暴露 i18n key，破坏可信度。
6. **控件呈现碎片化**：原生 `button/input/select/textarea` 与设计系统组件混用，
   高度、圆角、边框、hover、focus、disabled、loading 不一致。
7. **页面层级过弱**：标题、正文、辅助信息常仅靠字重区分；卡片、列表、属性栏、表单
   使用相近边界与底色，暗色模式尤为扁平。
8. **图标体系缺失**：导航无图标，顶栏使用字符或 emoji 充当命令、帮助、通知图标，
   尺寸、基线、笔画和跨平台渲染不可控。

### 2.3 P1：影响效率与品质的问题

- 看板、Issue 详情、成员、收件箱、聊天使用不同的工具栏、筛选、Tabs 与操作布局。
- Issue 详情桌面端表单化过强，正文、活动、评论与属性的主次关系不清；窄屏关系输入
  与选择控件拥挤。
- 列表和表格缺少统一的行高、数字对齐、截断、悬浮操作、空态与批量选择规则。
- 全局搜索外观像普通输入框，缺少快捷键提示、搜索范围和结果层级。
- 操作反馈偏“整块 Banner/Toast”，缺少字段级保存、乐观状态、撤销和重试模式。
- 亮/暗主题都有可读性基础，但只有少量表面 token 和单一阴影，无法精确表达
  canvas、sidebar、panel、raised、overlay 五层关系。
- 中文与英文混排缺少标点、数字、代码、长段落和表格数字的排版规则。
- 当前视觉门禁固定在 1024/768 两档，无法发现 1440px 的空间浪费和 390px 的触控、
  换行、横向溢出问题。

## 3. 信息架构与全局壳层

### 3.1 桌面导航

桌面壳层由 48px 顶栏、240px 可折叠侧栏和流式主区组成。侧栏不再平铺 15 项，按用户
心智分为：

| 分组 | 入口 |
| --- | --- |
| 日常 | 首页、收件箱、我的工作 |
| 工作 | 项目、Issue、看板、周期 |
| 协作 | 成员、聊天、小队 |
| 自动化 | Autopilot、运行时、技能、集成 |
| 分析 | 洞察 |
| 底部固定 | 个人设置；工作区设置仅 admin/owner 可见 |

规则：

- 每个入口使用同一套 16px 线性图标 + 文案；禁止 emoji 和字符充当产品图标。
- 当前项用“浅强调底 + 强文本 + 左侧 2px 指示”表达，不用整块高饱和色填满侧栏。
- 分组可折叠，但“日常”默认展开；折叠侧栏保留图标和 Tooltip。
- Autopilot、运行时与技能必须使用不同中文名称；不得出现两个同名一级入口。
- `/skills` 等所有可见导航必须有可用路由；新增导航需通过路由一致性测试。

### 3.2 顶栏

- 左侧为产品标识与当前工作区切换；中部为全局搜索触发器；右侧为连接态、收件箱、
  帮助与账号菜单。
- 搜索触发器不是自由输入框：显示搜索图标、提示文案和 `⌘/Ctrl K`，点击后打开命令
  面板。
- 实时连接态仅在异常或同步时显式占位；稳定连接不长期占据高注意力空间。
- 顶栏阴影仅在页面滚动后出现；静止时以细边界分层。

### 3.3 移动端导航

- 视口 `<768px` 使用 48px 顶栏 + 底部导航：收件箱、我的工作、看板、聊天、更多。
- “更多”打开全高抽屉，承载项目、成员、自动化、分析和设置；当前项状态同步。
- 深页顶栏提供返回、标题和最多两个高频动作；其余动作进入溢出菜单。
- 移动端保留建 Issue、更新状态、评论、搜索、切换工作区等关键写路径，不以“只读
  优先”为由删除。

## 4. 设计 token

所有 token 维护在 `tokenValues.ts` 单一事实源并生成 CSS。组件不得直接使用 primitive
色值；primitive 只服务于语义 token 映射。

### 4.1 颜色与表面

至少补齐以下语义层：

- 背景：`canvas`、`sidebar`、`surface`、`surface-subtle`、`surface-raised`、
  `surface-overlay`、`surface-hover`、`surface-selected`。
- 文本：`text-strong`、`text-primary`、`text-secondary`、`text-tertiary`、
  `text-disabled`、`text-inverse`、`text-link`。
- 边界：`border-subtle`、`border-default`、`border-strong`、`border-focus`。
- 操作：primary / neutral / danger 的 default、hover、pressed、disabled。
- 状态：success / warning / danger / info 各有 foreground、background、border，
  不复用“纯状态色”同时承担文本和大面积背景。

亮色以中性灰和低饱和强调为主；暗色使用接近黑的 canvas 与逐级抬升表面，边界亮度
随层级增加，禁止所有面板都使用同一蓝灰色。

### 4.2 排版

生产字体必须自托管或使用稳定系统回退，不依赖运行时第三方字体请求。推荐字体栈：
西文 UI 字体 + 中文无衬线字体 + 系统回退；代码、ID 和日志使用等宽字体。

| token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `label-xs` | 12 / 16 | 徽标、时间、辅助元数据 |
| `body-sm` | 13 / 20 | 紧凑列表、导航、表头 |
| `body-md` | 14 / 22 | 默认正文、表单 |
| `body-lg` | 16 / 24 | 长文、空态说明 |
| `title-sm` | 18 / 24 | 卡片或区域标题 |
| `title-md` | 22 / 28 | 页面标题 |
| `title-lg` | 28 / 36 | 登录、空工作区等聚焦页 |

规则：

- 中文正文默认 14/22 或 16/24，不使用 16/24 以下行高承载长段落。
- Issue key、版本、数量、日期、百分比使用 tabular numbers；日志与命令使用等宽字体。
- 页面标题最多一行；副标题最多两行；表格单元格默认单行截断并提供 Tooltip。
- 辅助文字不以低对比度代替层级；两主题均满足 theme.md 的对比度门禁。

### 4.3 尺度、形状与层级

- 间距：2、4、6、8、12、16、20、24、32、40、48、64px。
- 控件高度：紧凑 28px、默认 32px、宽松 36px；触屏交互热区最小 44×44px。
- 圆角：4px（徽标/小控件）、6px（默认控件）、8px（卡片）、12px（弹层）、
  full（头像/状态点）；禁止所有区域统一大圆角。
- 阴影：`xs`（浮动工具）、`sm`（菜单）、`md`（Dialog/Drawer）；暗色单独校准。
- 层级：base、sticky、dropdown、overlay、toast、command-palette 六档 z-index token，
  页面 CSS 不得写任意 z-index。
- 布局 gutter：手机 16px，平板 20px，桌面 24px，大屏 32px。

### 4.4 动效

- 时长：80ms（pressed）、120ms（hover/focus）、180ms（菜单/Popover）、240ms
  （Drawer/Dialog）；统一 standard 与 emphasized easing。
- 动效只解释状态或空间关系：菜单展开、拖拽落点、乐观保存、列表插入、页面抽屉。
- 不对大面积背景、长列表或首次渲染做装饰动画。
- `prefers-reduced-motion` 下取消位移与循环动画，保留即时状态变化。

## 5. 组件收敛契约

实施前先补齐设计系统，业务页面只组合组件，不复制其内部样式。

### 5.1 必备基础组件

- 操作：Button、IconButton、SplitButton、LinkButton。
- 表单：Field、Input、Textarea、Select、Combobox、Checkbox、Radio、Switch、
  DateInput、SearchField。
- 状态：Badge、StatusIcon、Avatar、AvatarGroup、Progress、Skeleton、Spinner。
- 导航：Tabs、SegmentedControl、Breadcrumb、Pagination、SideNavItem、BottomNav。
- 浮层：Tooltip、Popover、Menu、Dialog、Drawer、CommandPalette。
- 容器：PageHeader、Toolbar、Card、ListRow、DataTable、DetailPanel。
- 反馈：InlineMessage、Banner、Toast、EmptyState、ErrorState、OfflineState。

### 5.2 状态与行为

每个交互组件必须覆盖 default、hover、focus-visible、pressed、disabled、loading、
invalid；选中态与焦点态不可混为一体。

- 破坏性操作使用二次确认，并明确对象名称和不可逆影响。
- 保存型表单支持字段级错误；服务器错误保留用户输入并提供重试。
- 乐观操作显示“保存中/已保存/失败”状态；可撤销操作优先提供 5 秒撤销。
- 菜单、Dialog、Drawer 完整处理 focus trap、Escape、点击外部关闭与焦点归还。
- Tooltip 不承载完成任务所必需的信息；触屏上不存在仅 hover 可达的动作。

### 5.3 收敛门禁

- 业务层原则上禁止新增裸 `button/input/select/textarea`；确有语义需求须写行级说明。
- 图标只从统一 Icon 组件入口导入；禁止在产品 UI 使用 emoji、字符或外部图片充当图标。
- 页面不得定义与设计系统重复的按钮、字段、Tabs、徽标、弹层和空态样式。

## 6. 页面模板与逐域目标

### 6.1 布局模板

| 模板 | 目标 |
| --- | --- |
| 聚焦表单 | 登录、注册、重置：`max-width: 400px`，单一主操作，错误就地恢复 |
| 列表/表格 | 页面头 + 工具栏 + 内容；桌面最大 1200px，大屏可放宽；行高 40/48px |
| 看板 | 主区全宽、横向列滚动、工具栏 sticky；列宽 280–320px，不出现无意义空白 |
| 详情 | 主内容 `minmax(0,1fr)` + 320px 属性栏；平板下属性栏变 Drawer，手机单列 |
| 对话 | 会话列表 280–320px + 弹性消息区；手机在列表/对话间路由切换 |
| 设置 | 侧级导航 + `max-width: 720px` 表单；危险区与常规设置物理分离 |
| 仪表盘 | 12 列网格；摘要、趋势、明细三层；图表有表格/文字替代 |

### 6.2 页面族差距与目标

| 页面族 | 当前主要差距 | 目标状态 |
| --- | --- | --- |
| 登录/找回/设备授权/邀请 | 脚手架文案、开发入口、错误过泛 | 干净品牌页；区分凭据错误、网络错误、服务不可用；保留输入并可重试 |
| 首页/工作区 | 演示组件、无真实任务聚合 | 最近工作、我的任务、待审批、agent 运行状态与快速创建组成真实首页 |
| 项目/周期/Issue 列表 | 筛选与操作样式分散 | 统一 PageHeader/Toolbar/DataTable；保存视图与批量操作渐进披露 |
| 看板 | 宽度浪费、原生控件、卡片层级弱 | 全宽列、清晰拖拽落点/WIP、卡片元数据稳定、移动端按列切换 |
| Issue 详情/评论 | 表单感强、属性与内容争夺注意力 | 标题/描述/活动为主；属性桌面侧栏、移动 Drawer；评论动作按需显现 |
| 收件箱 | 信息组层级弱、操作像普通文字 | 未读/优先级/来源清晰；组内摘要、快速处理、撤销与归档反馈一致 |
| 成员/Agent/小队 | 1024px 溢出、长文案破表、类型表达粗糙 | 响应式表格转卡片；人/agent 同册且类型、角色、容量可快速扫描 |
| 聊天 | 面板表面偏重、消息与上下文层级弱 | 会话列表、上下文、消息、生成态、输入区四层明确；手机列表/会话分屏 |
| Autopilot/运行时/技能/集成 | 管理表单密集，多个模块同名 | 自动化运营区统一 IA；概览→详情→编辑，风险设置渐进披露 |
| 设置/数据管理 | 页面结构与危险操作不统一 | 统一设置模板、保存状态、权限隐藏；导入导出显示可恢复进度 |
| 洞察 | 图表与筛选缺统一密度 | 摘要数字、趋势图、明细表层级稳定；双主题色板和非颜色信号完整 |
| 搜索/命令面板 | 顶栏像普通输入，结果状态弱 | 分组结果、键盘选中、最近项、空态、权限过滤与规范深链统一 |

## 7. 响应式与触控规则

以内容行为而非设备名称决定断点：

- `<640px`：手机单列；底部导航；详情属性、筛选和次要操作进入 Drawer。
- `640–767px`：宽手机/小平板，表单可双列但主要阅读区仍单列。
- `768–1023px`：平板；侧栏收起；表格保留关键列，其余进入行详情。
- `1024–1279px`：紧凑桌面；侧栏可折叠，禁止成员表等内容横向裁切。
- `≥1280px`：完整桌面；看板、对话、详情双栏充分利用空间，阅读页仍限制行宽。

硬规则：

- 320、390、768、1024、1440px 均不得出现页面级横向溢出；看板列轨道和 DataTable
  是允许横向滚动的显式容器。
- 移动端固定区域不得同时遮挡顶部标题、底部导航和软键盘。
- 触屏目标最小 44×44px，相邻危险与常规操作至少间隔 8px。
- 所有 hover 操作在触屏有常驻、菜单或长按之外的等价入口。

## 8. 状态、文案与可访问性

### 8.1 状态

所有路由至少具备 loading、empty、error、permission、offline、stale/resync 六态；含
批量操作的页面另有 partial failure。错误块必须包含：

1. 用户可理解的发生原因；
2. 当前数据是否安全、操作是否已提交；
3. 主要恢复动作；
4. 必要时的替代路径或联系对象。

禁止把所有失败统一显示为“网络错误”。登录、权限、校验、冲突、限流、离线和服务端
故障必须区分。

### 8.2 文案

- 页面使用“动词 + 对象”的动作命名，如“新建 Issue”“重试上传”，避免含糊的“确认”。
- 中英文与数字之间按排版组件处理，不在消息文本中人工堆空格。
- UI 不得暴露 i18n key、内部枚举、HTTP 状态或堆栈；技术详情可折叠并支持复制。
- 空态说明“为什么为空 + 下一步”，有权限时提供一个主操作，无权限时不展示假按钮。

### 8.3 无障碍

- WCAG 2.1 AA 为最低线；焦点顺序与视觉顺序一致，键盘可完成全部关键流程。
- 图标按钮有可读名称；状态不只靠颜色；表格有表头与排序状态；图表有文字摘要。
- Dialog/Drawer/菜单使用正确语义和焦点管理；动态保存、上传与生成状态使用
  `aria-live`，但避免重复播报。
- 200% 缩放下关键操作可用，400% 缩放下不要求保持多栏但不得丢失内容。

## 9. 实施顺序与依赖

### Stage 0：清障

- MES-107 完成首页、登录页和占位清理。
- 修复导航断链、同名入口、移动端无导航、i18n key 泄露。
- 建立全路由清单和页面负责人，不允许“看起来像没做完”的页面留到最后。

### Stage 1：系统层

- 扩充 token、图标、排版与壳层。
- 补齐 §5 基础组件并迁移裸控件；先做 Story/fixture 状态矩阵。
- 新旧组件不可长期并存；每个迁移切片删除对应页面私有实现。

### Stage 2：高频关键路径

- 登录 → 首页 → 建 Issue → 看板拖拽 → Issue 详情/评论 → 收件箱 → 搜索。
- 先完成桌面与手机，再补平板适配；亮/暗主题在同一 PR 完成。

### Stage 3：协作与自动化

- 成员/Agent/小队/聊天。
- Autopilot/运行时/技能/集成。

### Stage 4：管理与分析

- 项目设置、工作区设置、标签/自定义字段、数据导入导出、洞察。
- 统一空态、错误态、权限态和长数据压力场景。

### Stage 5：质量收口

- 视觉回归、真实 E2E、键盘/读屏、触控、性能与跨浏览器走查。
- 修复后只更新基线，不以提高截图阈值、mask 大面积内容或隐藏溢出来“通过”。

Stage 1 的 token/组件可与 MES-107 并行，但不得同时修改首页/登录页重叠代码。页面级
实施必须同时满足：MES-107 已完成、设计基线已合入、对应基础组件已就绪。

## 10. 验收门禁

### 10.1 自动化

- 路由一致性：所有可见导航均可达，无重复文案、无 NotFound、无无权限入口泄露。
- 文案清洁：无 demo/placeholder/phase/coming soon 残留，无 i18n key 渲染。
- 组件收敛：业务层新增裸交互标签、emoji 图标、硬编码色值和任意 z-index 均阻断 CI。
- 视觉回归：
  - 每个页面模板至少一条稳定真实数据用例；
  - light/dark；
  - 1440×900、1024×768、768×1024、390×844；
  - 关键页面补 loading/empty/error；
  - 失败上传 actual/expected/diff，阈值不高于现有 1%。
- 溢出检测：320/390/768/1024/1440px 扫描所有路由，除声明容器外
  `scrollWidth <= clientWidth`。
- a11y：自动检查 + 键盘焦点快照；颜色、名称、角色、Dialog 和表单错误零严重问题。

### 10.2 真实流程

以下流程必须以真实后端、桌面与手机、双主题各完成一次：

1. 未登录访问 → 登录 → 切换工作区；
2. 新建 Issue → 修改属性 → 看板拖拽 → 冲突/失败恢复；
3. 评论、@ 提及、附件上传 → 收件箱查看并处理；
4. 全局搜索/命令面板 → 规范深链打开资源；
5. 创建或配置 agent → 分派 → 查看运行/日志/失败恢复；
6. 创建与编辑自动化 → 查看 run；
7. 断网 → 恢复 → stale/resync 收敛；
8. 手机端底部导航、更多抽屉、详情属性 Drawer 与软键盘交互。

### 10.3 完成定义

- 42 个现有路由均完成清单走查，新增路由同步纳入。
- 桌面、平板、手机无阻断级布局或触控问题；亮/暗均无临时补丁观感。
- 所有关键路径最多一个明确主操作，错误均有可执行恢复入口。
- 不存在脚手架、占位、原始 key、重复入口、裸控件视觉或跨平台 emoji 图标。
- UT、真实 E2E、视觉回归、对比度与构建全部通过；文档与实现一致。
