# 全局搜索 / 命令面板 + 键盘快捷键体系 调研记录

> 调研对象:主流团队协作 / 项目管理产品在【全局搜索 / 命令面板 / 键盘快捷键】模块上的**通用设计模式**(已匿名化,不指向任何具体产品)。
> 数据模型基准约定:PostgreSQL、UUID 主键、`created_at` / `updated_at`、REST + JSON、游标分页、Bearer token、WebSocket 实时。
> 本模块是**横切导航与效率层**:不新增核心业务实体,而是把 issue / 成员 / agent / 项目 / 视图 / 聊天会话等既有资源,通过统一检索入口与键盘体系加速访问。对齐 README §6.12(命令面板 + 快捷键硬约束)、§6.14(API 包络)、§6.2 / §6.7(权限过滤)、§6.19(favorites)。

| 使用频率加权 | 高频项排序加权 | **可选增强** | 常用项更靠前 |
| 键盘导航 | ↑/↓ 移动选中、Enter 执行、Esc 关闭、Tab 补全选中文本到输入框 | **必备** | 纯键盘操作 |
| 深链跳转 | 选中对象结果跳转到规范深链:`/w/{ws}/issues/by-identifier/{KEY-N}`、`/w/{ws}/projects/{id}`、`/w/{ws}/agents/{id}`、`/w/{ws}/executions/{id}`、`/w/{ws}/chat/{session_id}`、`/w/{ws}/approvals`(README §6.12) | **必备** | 结果即入口 |
| 创建类快捷动作 | 面板内「新建 issue/项目/聊天」并可预填(如 `> 新建 issue 标题`) | **必备**(新建 issue,等价 `C`)/ 其余可选 | 快速建对象 |
| 作用域前缀(scoped mode) | `>` 切纯命令模式、按类型筛选(如只看 issues) | **可选增强** | 精确收窄 |

| 功能点 | 说明 | 级别 |

### 1.3 键盘快捷键体系

| 分组 | 快捷键(主流通用映射) | 级别 |
|------|------------------------|------|
| **全局组** | `Ctrl/Cmd+K` 命令面板;`/` 聚焦搜索;`C` 新建 issue;`?` 快捷键帮助层;`G` then `I`/`B`/`M`/`A` 跳收件箱/看板/成员/自动化(README §6.12);`Esc` 关闭弹层/返回;`Ctrl/Cmd+/` 帮助层(备选) | **必备** |
| **看板组** | `C`/`N` 当前列新建卡片;`F` 打开筛选;`[`/`]` 切换/折叠列;选中卡片后 `Enter` 打开、`E` 编辑、`S` 改状态、`A` 改 assignee;`↑↓←→`/`J K H L` 在卡片间移动 | **必备**(核心)/ 移动键可选 |
| **issue 详情组** | `E` 编辑标题/描述;`S` 改状态;`A` 改 assignee;`P` 改优先级;`X` 关闭抽屉;`Ctrl/Cmd+Enter` 提交评论;`←/→` 上/下一个 issue | **必备**(核心)/ 翻页可选 |
| **聊天组** | `Ctrl/Cmd+K` 或 `↑` 聚焦输入/历史;`Enter` 发送、`Shift+Enter` 换行;`Ctrl/Cmd+↑` 编辑上一条;`Esc` 退出会话 | **必备**(核心) |
| **序列键(chord)** | `G` 为首键的序列(`G I`/`G B`/`G M`/`G A`),带**超时窗口**(默认 ~800ms–1s,超时或按 Esc 取消);首键按下时 UI 给「等待第二键」提示 | **必备**(README 已用 `G then …`) |
| **`?` 帮助层** | 弹出层列出**当前上下文全部可用快捷键**,随上下文(全局/看板/issue 详情/聊天)分组,实时反映;支持搜索过滤(可选) | **必备** |
| **输入框豁免** | 焦点在 `input`/`textarea`/`select`/`contenteditable` 时,**单字符快捷键一律不触发**;仅放行显式 `Ctrl/Cmd` 组合(如 `Ctrl/Cmd+K`、`Ctrl/Cmd+Enter`)与 `Esc`/`Tab`/`Enter` 等表单语义键 | **必备**(README §6.12) |
| **等价鼠标路径** | 一切快捷键操作均有可达的鼠标路径(菜单/按钮);快捷键是**加速**而非唯一入口 | **必备**(README §6.12) |
| **平台键自适应** | macOS 显示 `⌘`/`⌥`,Windows/Linux 显示 `Ctrl`/`Alt`;帮助层按平台渲染 | **必备** |
| **自定义快捷键(rebind)** | 用户自定义/改键编辑器 | **可选增强**(建议起步**不做**,见 §7) |

## 2. 数据模型

**核心结论:本模块几乎不新增持久化实体**——命令注册表、快捷键表、分组配置都是**前端代码常量**(随版本发布),不进数据库。仅「跨设备最近项」在需要时才落表。

| 候选数据 | 落地方式 | 说明 |
|----------|----------|------|
| 命令 / 快捷键注册表 | **纯前端常量** | `{ id, title, shortcut, group, when(上下文谓词), handler, keywords }` 数组,无表 |
| 最近使用(recents) | **起步纯前端**(localStorage,按 user 隔离);需跨设备时建 `recent_items` | 见下 |
| 快捷键自定义 | **不做 → 无表**;做则 `user_keybindings` | 建议起步不做(§7) |
| 搜索历史 | **纯前端** 或 不持久 | 隐私优先,默认不落服务端(见 §6) |

### 2.1 `recent_items`(仅当需要跨设备同步最近项时,可选增强)

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | |
| `workspace_id` | UUID | NOT NULL, FK ON DELETE CASCADE | 隔离键 |
| `member_id` | UUID | NOT NULL, FK→members(workspace_id,id) ON DELETE CASCADE | 私有于成员 |
| `target_type` | TEXT | NOT NULL, CHECK IN ('issue','project','view','chat_session','member','agent','command') | 与搜索对象类型 + 命令一致 |
| `target_id` | UUID | NULL | 多态逻辑外键(§6.2 第 4 条,行携带 workspace_id);`command` 类为 NULL,用 `command_key` |
| `command_key` | TEXT | NULL | 命令类最近项(如 `issue.create`) |
| `last_used_at` | TIMESTAMPTZ | NOT NULL DEFAULT now() | 排序键 |
| `use_count` | INT | NOT NULL DEFAULT 1 | 频率加权(可选) |
| UNIQUE | `(member_id, target_type, COALESCE(command_key, target_id::text))` | | 去重 upsert |

```sql
CREATE INDEX idx_recent_member ON recent_items (workspace_id, member_id, last_used_at DESC);
```

> 与既有模型关系:
> - **favorites(§6.19)**:已是成员私有快速入口,`target_type IN ('issue','project','view','chat_session')`。命令面板**空态「收藏区」直接复用** `GET /api/v1/favorites`,无需新建。recents 与 favorites 语义互补(最近 vs 主动固定),可并存。
> - **views(kanban.md)**:`view` 是搜索对象之一,搜索命中后跳视图深链;不需要为搜索改动 views 表。
> - **members / agents(member.md)**:统一名册,搜索 member/agent 即查 `members`(JOIN `member_type`),无新表。

### 2.2 检索索引策略(PostgreSQL 起步)

- issue:`identifier` 等值(唯一索引已有)+ `title` 前缀/三元组(`pg_trgm` GIN)模糊;
- 成员/agent:`members` 显示名 `pg_trgm` GIN;
- 项目:`projects.name` `pg_trgm` GIN;视图:`views.name`;聊天会话:标题 + 参与者过滤;
- 全部查询带 `workspace_id` 复合前缀(§6.2),`statement_timeout` 兜底(§6.14)。

## 3. 接口设计

REST 基础路径 `/api/v1`,Bearer token,游标分页(§6.14)。

### 3.1 端点清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/search?q=&types=&limit=&cursor=` | 全局搜索(对象 + 可选命令由前端本地合并) |
| GET | `/search/suggest?q=` | typeahead 建议(可选增强) |
| GET | `/favorites`(§6.19 已有) | 空态收藏区数据源,无需新增 |

> 命令(command)条目**由前端本地过滤**(命令注册表是前端常量,无需服务端),服务端只返回对象类结果;前端把本地命令命中与服务端对象命中**在客户端合并分组**。

### 3.2 请求

```
GET /api/v1/search?q=login&types=issue,member,agent,project,view,chat_session&limit=20&cursor=<opaque>
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `q` | string | 查询词;空/缺省 → 返回默认集(recents/favorites,可选) |
| `types` | csv | 限定对象类型;缺省=全部可见类型 |
| `limit` | int | 默认 20,上限 50(对齐 §6.14 过滤限制精神) |
| `cursor` | opaque | 整体游标(§6.14),base64 编码 `(score, type, id)` |

### 3.3 响应(遵循 §6.14 包络)

```json

      "id": "iss_uuid",
```

**结果条目统一形状**(前端按此渲染,无论类型):

| 字段 | 必备 | 说明 |
|------|------|------|
| `type` | ✓ | `issue`/`member`/`agent`/`project`/`view`/`chat_session`(与命令 `command` 前端合并) |
| `id` | ✓ | UUID(命令类用前端 `command_key`) |
| `title` | ✓ | 主标题(issue 标题 / 成员 display_name / 项目名…) |
| `subtitle` | ✓ | 副标题(identifier、归属、状态等上下文) |
| `icon` | ✓ | 类型图标键(语义,不硬编码) |
| `url` | ✓ | 规范深链(§6.12),Enter 直达 |
| `badge` | – | 状态/类型徽章(可选,语义色 token) |
| `score` | – | 排序分(可选,调试/二次排序) |
| `highlight` | – | 命中区间(可选高亮) |

### 3.4 权限过滤语义(对齐 §6.2 / §6.7)

- **服务端在查询内过滤,而非取出后裁剪**(否则破坏分页计数与游标稳定性,并经计数/facet 泄漏受限资源存在性)。
- 逐资源重新授权(与 §6.7 订阅授权一致):
  - **issue**:工作区成员资格 + 所属项目可见性(私有项目仅其成员可见)+ issue 级可见性;
  - **project**:按项目可见性(私有项目仅成员);
  - **member / agent**:工作区成员名册可见(全员可见名册,guest/agent 受限按 §6.12 角色矩阵);
  - **view**:私有视图仅 owner,共享视图按工作区/项目成员;
  - **chat_session**:会话参与者。
- **私有项目结果不得越权**:命中私有项目内 issue 时,非成员**完全不可见**(连「存在性」都不暴露),与「私有项目事件只进 `project:{id}` 频道、不广播后前端过滤」同源原则。
- 多租户:搜索 SQL 一律带 `workspace_id` 谓词 + 复合 FK / RLS 兜底(§6.2);**绝不**仅靠前端过滤隔离。

### 3.5 错误码与限制(对齐 §6.14)

| HTTP | code | 场景 |
|------|------|------|
| 400 | `validation_error` | 非法 `types` / `limit` 超限;`q` 过长 |
| 400 | `filter_too_complex` | 组合条件过深(若支持高级过滤) |
| 401 | `unauthorized` | 无/失效 token |
| 403 | `forbidden` | 非工作区成员 |
| 422 | `query_cost_exceeded` | 估算成本超限,建议收窄 `types`/加长 `q` |
| 429 | `rate_limited` | 限流(带 `Retry-After`) |

> 服务端以 `statement_timeout`(默认 3s,§6.14)+ 查询成本估算兜底;错误 `message` 不泄漏 SQL/堆栈/内部 ID。identifier 精确命中走等值索引快路径,不计入模糊成本。

### 4.2 状态矩阵(对齐 §6.12 核心页面异常态)

| 状态 | 呈现 |
|------|------|
| loading | 输入后即显 skeleton 行 / 顶部细进度条;首屏可先渲染本地命令命中(零延迟),对象结果异步补入 |

| permission denied | 面板可用但越权类型不返回;不暴露存在性 |
| error / retry | 内联错误行 + 「重试」按钮(toast 兜底) |
| offline | 仅本地命令可用,对象检索提示「网络已断开,显示本地命令」 |

## 5. UX 设计

### 5.1 模糊搜索排序(分层打分,主流通用做法)

匹配强度阶梯(强 → 弱),文本相关性主导、个性化仅做轻微加权/平局裁决:

```
精确匹配 > 前缀匹配 > 词首(token prefix)匹配 > 首字母缩略(acronym)
> 词边界/驼峰/路径分隔匹配 > 连续子串 > 子序列模糊 > (关键词/副标题兜底)
```

打分信号(示意权重,需实测调):
- **加分**:精确(+1000)、前缀(+700)、词首(+120/词)、缩略(+100)、词边界/驼峰/分隔(+30~40/字符)、连续命中段(+25/字符)、子序列字符(+5~15);**identifier 精确命中**直接顶置。
- **减分**:字符间隔(-5/跳过字符)、首命中位置靠后(-2/index)、标题过长(-0.1/字符)、未命中的查询词。
- **个性化**:recency / frequency / 上下文可用性(当前页可用命令)各**封顶**小幅加分,不得压过文本相关性。
- **稳定平局裁决**(确定性,避免结果「随机跳」):上下文相关性 → 最近使用 → 频率 → 标题更短 → 字典序 → 原始顺序。
- **归一化**:匹配前小写 + 去重音(NFKD),但**展示保留原文**;分词覆盖空格/`-`/`_`/`/`/`.`/驼峰边界。
- **黄金集评估**:维护 query→期望 top 结果 测试集,用 Top-1/Top-3 命中率、MRR 调权重,而非凭感觉。

### 5.2 防抖与延迟加载

- 命令面板**期望近乎即时**:本地命令过滤同步执行(零延迟先渲染);服务端对象检索**防抖 ~120–200ms** + **取消过期请求**(stale query cancel)。
- 大列表异步过滤;慢查询先渲染已有部分结果 + loading 指示。
- identifier 精确命中(如完整 `WEB-123`)可**跳过防抖**立即直达。

### 5.3 键盘优先交互流

- 打开即聚焦输入框;`↑/↓` 移动选中、`Enter` 执行/跳转、`Esc` 关闭、`Tab` 把选中文本补全回输入框(便于继续精修)。
- 鼠标悬停同步更新选中项,但不打断键盘焦点;支持鼠标点击直接执行。
- 误关后短时间重开可保留上次 query(可选)。

### 5.4 序列键超时窗口

- `G` 按下进入「等待第二键」态,UI 给轻量提示(如状态条 `G —`);**超时窗口默认 ~800ms–1s**,超时或 `Esc` 取消并清除缓冲;第二键到达即执行并清缓冲。
- 前缀冲突解析:首键命中多个序列时进入等待态(不立即执行),与单键命令冲突时序列优先等待。

### 5.5 无障碍 / 焦点管理(对齐 §6.12)

- 面板采用 **ARIA combobox + listbox** 模式:`role=combobox` + `aria-expanded` / `aria-controls` / `aria-activedescendant`;结果项 `role=option` + `aria-selected`。
- 结果数量变化用 `aria-live=polite` 播报;焦点管理可预测(打开陷落焦点、关闭归还触发元素)。
- 全键盘可达、焦点可见、Tab 序合理、Enter/Space 激活;命中高亮**不以颜色为唯一信号**。
- **尊重 `prefers-reduced-motion`**:浮层进出场动画、高亮脉冲在减少动效偏好下降级为即时/静态(同时遵循暗色 token 对比度 AA)。

### 5.6 实时性

- 本模块以**请求-响应检索**为主,不新增实时频道;结果项的实时状态(如 issue 状态、agent 容量「运行中 N/排队 M」)由各详情页订阅的既有频道(§6.7)承载,面板仅取**快照渲染**(badge 为服务端快照,真源在对应模块)。
- 事件词汇不新增(§6.7 注册表):搜索/快捷键不产生 realtime 事件。

## 6. 安全要点

| 维度 | 要求 |
|------|------|
| **跨租户隔离** | 搜索 SQL 一律带 `workspace_id` 谓词,复合 FK + RLS 纵深防御(§6.2);**禁止仅前端过滤隔离**;集成测试覆盖跨租户负向用例。 |
| **跨项目/跨资源越权** | 逐资源重新授权(项目可见性 / issue 可见性 / 会话参与者),私有项目命中对非成员**不暴露存在性**(不进结果、不进计数、不进 suggest);与 §6.7「私有项目事件不广播后过滤」同源。 |
| **不「先取后筛」** | 权限过滤下推到查询内,避免分页计数/游标失真与经计数泄漏受限资源。 |
| **搜索日志隐私** | 默认**不落服务端搜索日志**;若为改进排序需采集,仅聚合匿名化指标(命中率/MRR),**不存可关联到个人的原始 query**;query 含敏感内容(可能粘贴凭证)——禁止进日志/错误上报/通知。 |
| **注入防护(SQL)** | 参数化查询;`LIKE` 通配符(`%` `_` `\`)转义;`types` 白名单校验;`limit` 上限约束;`statement_timeout` + 成本估算兜底(§6.14)。 |
| **注入防护(XSS)** | 高亮以**命中区间(offset/length)**返回,前端按区间渲染,**不回显 HTML 字符串**;title/subtitle 一律转义后渲染。 |
| **输入校验** | `q` 长度上限、`types` 枚举校验、`cursor` 不透明且服务端签名/校验,非法即 400;错误 message 不泄漏内部细节(§6.14)。 |
| **限流** | 搜索端点纳入限流中间件(§6.14 429 + `Retry-After`),防枚举/防 DoS。 |

## 7. 边界与非目标(YAGNI)

**起步明确不做(建议):**

| 非目标 | 理由 / 建议 |
|--------|-------------|
| **独立全文检索引擎**(外部搜索引擎/索引集群) | 起步用 PostgreSQL(`pg_trgm` 三元组 + GIN / `tsvector`)即可满足标题 + identifier 检索;description/评论正文全文检索列为**可选增强**,待数据量与需求真实出现再演进,避免引入额外运维与再索引复杂度。 |
| **OCR / 附件内容搜索** | 附件仅按文件名/标题命中(attachment.md),不做内容级检索。 |
| **自定义快捷键编辑器(rebind)** | 维护成本高(冲突解析/导入导出/帮助层联动),起步**只提供固定映射 + `?` 帮助层**;确有需要再做 `user_keybindings`。 |
| **跨设备 recents 同步** | 起步 recents 纯前端 localStorage;`recent_items` 表为可选增强。 |
| **搜索分析/个性化模型** | 起步仅 recency/frequency 轻量加权;不引入排序学习/埋点画像(兼顾隐私,见 §6)。 |
| **新增实时事件 / 频道** | 面板只读快照渲染,不产生 realtime 事件(§6.7 注册表不扩)。 |
